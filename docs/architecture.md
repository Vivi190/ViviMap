## ADR-1 — Native SwiftUI

- **Context:** No Mac; the only target is iPhone. CarPlay, Live Activities, CoreLocation and AVSpeech are native APIs.
- **Decision:**
  - Swift 6 language mode (full concurrency checking) and SwiftUI. Minimum iOS 17, required for `@Observable`, `CLBackgroundActivitySession` and `sensoryFeedback`.
  - Floating map controls use Liquid Glass on iOS 26 and a thin material on earlier versions.
- **Rejected alternative:** React Native: Android support is not a goal, and every native API would need a bridge.

## ADR-2 — Map engine

- **Decision:**
  - MapLibre Native iOS 7.0 (BSD-2) and `maplibre/swiftui-dsl` 0.27.0 (BSD-3, pinned to the exact version).
  - Styles are generated by `Tools/mapstyle/build_styles.py`: one layer definition, two palettes (day/night), OpenMapTiles schema.
  - Online tiles: OpenFreeMap. Offline, Planetiler will build PMTiles in the same schema (Phase 4), so one style set serves both.
- **Rejected alternative — Apple MapKit:**
  - No offline maps, no custom styles.
  - DPLA Attachment 6 §2.4 allows Apple data only on an Apple map.
  - Cannot be combined with our own routing engine.
- **Consequences:**
  - Label fonts are Noto Sans; SF Pro on the map is a licensing risk.
  - 3D buildings are hidden by default and shown in 3D mode.

## ADR-3 — Navigation core: Ferrostar

- **Decision:**
  - Use Ferrostar Core (route tracking, step advancement, deviation detection, snapping to the route).
  - Instruction cards, speed display and camera behaviour are our own SwiftUI components.
  - We generate Turkish voice prompts from the maneuver data **ourselves**; Valhalla's `tr-TR` translation is incomplete.
- **Risk:** Ferrostar 0.59 is tested with swiftui-dsl 0.26.1; we use 0.27.0. Phase 2 starts by confirming in CI that the two build together; otherwise pin to 0.26.1.
- **Rejected alternative:** Mapbox Navigation SDK. Proprietary; ToS §2.9.1 forbids use with MapLibre.

## ADR-4 — Routing: Valhalla

- **Decision:**
  - Online: Valhalla 3.9.x. FOSSGIS or Stadia's free plan during development; our own server long term.
  - Offline: `valhalla-mobile` (MIT, SwiftPM), through Ferrostar's `CustomRouteProvider` interface.
  - Both sides use the same tile build, so routes stay consistent offline.
- **Rejected alternatives:**
  - OSRM: produces no voice or banner instructions.
  - GraphHopper: no offline support on iOS.
  - Organic Maps: no SDK; cannot be used as a library.

## ADR-5 — Route intelligence (what sets the project apart)

```
                ┌───────────── RoutingEngine ─────────────┐
 Start/End ────►│ Candidates (Valhalla, no traffic):      │
                │  • default + 2 alternatives             │
                │  • "Local streets" (use_highways↓)      │
                │  • avoid the D-100/E-5 corridor         │
                │    (linear_cost_factors)                │
                │ Dedup: geometric overlap > 85%          │
                │  counts as the same route               │
                └────────────────┬────────────────────────┘
                                 ▼
                ┌───────────── TrafficEngine ─────────────┐
                │ All candidates scored by ONE provider   │
                │ (HERE import / via-points) → one scale  │
                │ duration, typicalDuration, baseDuration │
                └────────────────┬────────────────────────┘
                                 ▼
                ┌──────────── Decision layer ─────────────┐
                │ score = duration + uncertainty margin   │
                │  + turn/junction/signal penalty         │
                │ Navigating: gain ≥ max(3 min, 15%)      │
                │  and cooldown ≥ 3 min; no reroute offer │
                │  within 300 m of a maneuver             │
                └─────────────────────────────────────────┘
```

- **Durations from different providers are never compared.** All candidates use the same traffic provider.
- **Speeds are not invented for side streets without traffic data.** Road class, traffic lights and turn count enter the score as an uncertainty margin.
- The thresholds (3 min, 15%, 300 m) are **initial estimates**, to be tuned with real drives in Phase 8.
- A "better than Google or Yandex" claim needs measurement. Phase 7 records predicted and actual duration for every drive.

## ADR-6 — Search

- **Decision:**
  - Online: Photon, on the public server during development, then our own.
  - A place-type word in the query (*durak*, *istasyon*/*metro*/*marmaray*, *AVM*, *iskele*: stop, station, mall, pier) triggers a concurrent second request without that word, using Photon's `osm_tag` filter. Measurement: [2026-11-14-arama-olcumu.md](research/2026-11-14-arama-olcumu.md) (Turkish).
  - Addresses arrive as written in messages ("Atatürk Cad. No:12 D:5 Kartal/İstanbul") and are rewritten to OSM spelling first (Caddesi, 12; flat and floor dropped). The match on street and number ranks first, then the street.
  - A bare place type ("benzinlik", "en yakın eczane") skips text search: Photon's reverse search with an `osm_tag` filter returns the nearest first. Offline, the same types come from the on-device index, nearest first.
  - "District + type" ("esentepe eczane") returns the nearest around that district; if "district + brand" ("kurtköy migros") returns nothing, the brand is searched again around the district. The district comes from the on-device index (the nearest of any namesakes); builds without the index send the query as is.
  - Rail lines and planned or under-construction roads sink to the bottom.
  - Reverse geocoding (picking on the map) also uses Photon, not Nominatim.
  - Offline: a SQLite FTS4 index built in CI (Istanbul, Turkish folding: "çanakkale" = "canakkale"). Takes over when Photon is unreachable or returns an error (5xx, 429).
- **Why no Apple search:** DPLA Attachment 6 §2.4.
- **Known limit:** house-number coverage in OSM is low. A missing number falls back to the street, marked "approximate".

## ADR-7 — Privacy and security

- Location history and personal statistics stay on the device. No analytics or third-party tracking SDKs.
- API keys (HERE, Stadia) are not in the code.
  - They are injected at build time: `HERE_API_KEY` GitHub Secret → build setting → Info.plist (`HEREAPIKey`).
  - The key is plain text in the app bundle, readable by anyone who unpacks it. Accepted for private TestFlight use; if usage grows, the key moves behind a small proxy. Keychain would not help.
  - A monthly quota guard for paid APIs (`RequestBudget`) keeps each device under half the free quota, so two phones can share one key at no cost.
- Signing material lives only in GitHub Secrets and is wiped from the runner after each workflow. `.gitignore` keeps these files out of the repository.
- Offline packages (Phase 4) are verified with SHA-256.

## ADR-8 — Build and distribution

- **XcodeGen:** `.xcodeproj` is generated from `project.yml` and is not committed.
- **CI (`ci.yml`):** every push: build, unit tests and day/night simulator screenshots, kept as artifacts.
- **TestFlight (`testflight.yml`):** manual trigger only. Manual signing; `xcodebuild -exportArchive` with `destination=upload`.

## ADR-9 — Speed camera warnings

- **Decision (2026-11-13):** camera warnings are included (owner decision).
- **Data sources:**
  - OSM `highway=speed_camera`: 184 points in Istanbul, 1 in Pendik.
  - Official fixed EDS (traffic enforcement) camera locations, if a machine-readable source is found.
  - User-marked points.
- **Known risk:** KTK (Turkish Highway Traffic Law) Art. 51 (Law No. 7574) bans radar detection/warning *devices*; whether a phone app is covered is disputed. Owner decision; this note is for the record only.
